# S2 · Backend Apps Script — Plan de implementación

> **Para quien ejecute:** usar superpowers:executing-plans (en línea). Los pasos usan casillas `- [ ]`.

**Meta:** implementar todo `api-panel.md` y `api-publica.md`: datos sobre Sheets, CRUD con versiones e historial, fotos, motor de precios, `publicar()`, estadísticas, documentos, `instalar()` completo y la API pública con eventos.

**Arquitectura:** código GAS V8 plano (un ámbito global, sin `import`), en archivos pequeños por responsabilidad. Lo puro (precios, armado de la copia, validación de eventos) se separa de lo que toca Google, para probarlo a fondo. Los tests usan `cargarGas` y los dobles de S1, que se amplían con su propio test cuando falta algo.

**Stack:** Apps Script, Vitest, `@catalogo/contratos` (`validarCatalogo`, `porcentajeDescuento`, `revisarPaleta`).

**Spec:** `docs/superpowers/specs/2026-11-20-catalogo-ropa-design.md` y `docs/contracts/` (`modelo-datos`, `api-panel`, `api-publica`, `documentos`, `README`).

## Restricciones globales
- Sin `import`/`export`. **Ningún código de nivel superior lee constantes de otro archivo** (el orden de carga de Google no es alfabético): los `const` globales son literales; todo lo demás va dentro de funciones.
- Helpers privados terminan en `_`. Toda función pública del Panel empieza con `requireAdmin_()`. Excepciones documentadas: `doGet`, `autorizar` y los envoltorios de activadores (`tarea*`, sin usuario activo).
- Nombres globales únicos entre archivos (un test los vigila). No usar `ISO_LIMA`, `RAW_FIXTURES`, `descargar_` ni `subirFotoDePrueba_` (son de `pruebas.js`, que sigue ahí).
- La API (`apps-script/api`) no define funciones que se llamen `crear*`, `guardar*`, `eliminar*`, `publicar*` ni `instalar*`.
- Sin ids, URLs, tokens ni correos en el código. Errores: `Error('<codigo>: detalle')` con los códigos del contrato.
- Fechas ISO con `-05:00` (`Utilities.formatDate`, zona `America/Lima`).
- Commits en español y con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Sin push, sin merge, sin `clasp`.

## Revisión enfocada (casos que el contrato no nombra y que muerden)
1. **El candado puede fallar en Google** (en el doble siempre se concede): `conCandado_` lanza `conflicto` y no escribe nada. Test con candado que falla.
2. **Fila editada a mano** (sin `version`, con celdas vacías, número en columna de texto): se lee sin romper y la primera edición no da `conflicto`.
3. **Oferta que no baja el precio** (redondeo, valor enorme): no cuenta; nunca sale una ventana con precio ≥ regular ni ≤ 0.
4. **Foto en la papelera, que no es imagen o inexistente**: `publicar()` lanza `invalido` con el código del producto y no guarda nada ni avisa a GitHub.
5. **Activador sin usuario activo**: `tarea*` hacen trabajo seguro e idempotente sin pedir `requireAdmin_()`; el resto de funciones públicas sí lo pide.
6. **Eventos hostiles** (`pg` con `=`, claves extra, tipos raros, 121 por minuto): se rechazan o se descartan sin escribir fórmulas.

## Decisiones donde el contrato calla (se explican en el informe)
- Fallo del candado → `conflicto`. Producto en borrador puede tener campos vacíos; al pasar a `publicado`/`agotado` se exige completitud.
- Alcance `seccion` de una oferta solo cuenta secciones `manual`, `categoria` y `etiqueta` (las automáticas serían circulares). Alcance `temporada` = prendas de las fotos de la temporada.
- Una oferta que, tras el redondeo, no deja el precio entre 0 y el regular se ignora. `precio_final` no se redondea. Los redondeos `entero` y `90` van siempre hacia abajo (el cliente nunca paga más de lo prometido); `90` = el `.90` inmediatamente inferior.
- Categoría no visible = sus prendas no se publican. `nuevo`/`ultimas_unidades`/`popularidad` solo con datos reales (`publicado_en`, `stock`, clics de WhatsApp en 30 días).
- `estadisticas_diarias` con `producto_id` vacío = eventos sin prenda (no es un total que duplique filas).
- `cambios_sin_publicar` se calcula con marcas en las propiedades del script (el Panel las actualiza en cada escritura).
- Activadores públicos: `tareaDiaria`, `tareaDocumentos`, `tareaReporteMensual` (envuelven `diario_`, `guardarDocumentos_`, `reporteMensual_`). Los documentos de una publicación los copia `estadoPublicacion()` al ver la ejecución terminada, o el activador cada hora.

## Estructura de archivos
| Archivo (`apps-script/panel/src/server/`) | Responsabilidad |
|---|---|
| `util.js` | errores, ids, fechas ISO, candado, marcas de cambios |
| `tipos.js` | listas, json y reglas de validación por columna |
| `hoja.js` | leer/escribir filas con tipos, config |
| `validacion.js` | reglas por entidad |
| `crud.js`, `historial.js` | CRUD, versiones, historial, deshacer |
| `precios.js` | motor de precios puro |
| `fotos.js` | subir, miniaturas, biblioteca, alta rápida |
| `ajustes.js` | arranque, textos, config, paleta |
| `catalogo.js`, `publicar.js`, `github.js` | copia publicada (pura), publicación, GitHub |
| `estadisticas.js`, `documentos.js`, `activadores.js` | consolidación, reportes, copias a Drive, triggers |
| `semillas.js`, `contraste.js` | **generados** por `apps-script/scripts/generar-semillas.mjs` |

Tests en `apps-script/test/panel/` y `apps-script/test/api/`.
